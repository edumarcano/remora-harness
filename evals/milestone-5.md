# Milestone 5 operational test packet

The specification owns scope and acceptance thresholds. This packet owns execution
preparation; dated records own actual outcomes. A prepared task or exit 0 is not a
semantic pass, native discovery proof, or milestone completion.

## Candidate and private inputs

Use a clean pinned distribution, or an explicitly identified synthetic committed
snapshot of development runtime inputs. Record its source revision and individual
runtime SHA-256 values, original repository base/diff identity, and host conditions.
Never transfer observations to changed runtime bytes without affected-case reruns.
Keep prompts, raw events, paths, snapshots, backups, private repositories, and scorer
material outside public records. A source snapshot is not a pushed PR candidate.

```text
python tools/prepare_trials.py --distribution "<pinned-source>" --output "<new-private-parent>"
```

This copies fixture inputs including hidden guidance, preserves unborn F01/F02,
creates independent baseline/Remora targets, and saves tasks.json outside targets.
Codex F05 treatment receives a pinned installation during controlled preparation
because this Windows sandbox protects existing skill directories. Its native
adoption/idempotence result is separate from unassisted first-install evidence.
It prepares 48 comparison tasks and nine functional tasks per host. Do not attach
tasks.json, this packet, rubrics, raw prior answers, or sibling targets to actors.
Preparation/collection helpers perform no semantic scoring or independent inference.

## Independent Codex execution

Inspect visible personal skill inventories first. Complete baselines before adding
a personal Remora bootstrap, or use a documented session-scoped exclusion and
verify the effective inventory. Do not alter global guidance or copy credentials.
In every session prohibit prior memory/answers and scorer access; review command
events for compliance and disclose unavailable/hidden context. Existing host memory
availability limits blinding even when no memory access is observed.

```text
python tools/run_codex_trials.py --tasks "<parent>/tasks.json" --condition baseline --results "<new-baseline-results>"
python tools/run_codex_trials.py --tasks "<parent>/tasks.json" --condition remora --results "<new-remora-results>"
python tools/run_codex_trials.py --tasks "<parent>/tasks.json" --condition functional --results "<new-functional-results>"
```

Between baseline and treatment, install the reviewed complete bootstrap package
into an unoccupied personal skill location using normal permission controls.
Capture the exact owned files and hashes. Never overwrite another personal skill.
Project skills are discovered directly from prepared targets. Verify native skill
metadata/activation and shared-resource reads in actual events; fallback does not
satisfy discovery. Run fresh sessions with default account model/effort, recorded
permissions, and no separate API. Collector timeouts/actor failures stop the cohort
for inspection; retries need fresh inputs and a new retained result directory.

Compare before/after inventories and actual commands, not final prose alone. Record
errors, misses, false positives, corrections, interruptions, instruction size, changed
files, and unavailable cost/token measurements. Do not infer human effort from actor
wall time. Use the existing content/unit checks as deterministic evidence only.

## Disposable Remora dogfooding

Use a complete disposable checkout distinct from the runtime distribution. Install
and adopt with bootstrap, preserving root guidance. Run native harness/documentation/
sampled-test audits. Plan, implement, and review one supported finding in fresh
sessions; the plan alone may cross the handoff. No finding is a valid audit result.

For a deterministic historical exercise, remove profiles/compatibility scanning
only in a separate disposable pre-fix reproduction. A broken link under profiles/
must escape the old checker and fail under the corrected checker. This is a
deliberately retained known defect, not a newly discovered product issue or holdout.
Use remora-fix-regression for the repair; demonstrate the exact red/green signal.
Preserve unrelated notes, requirements, guidance, and managed assets throughout.
Integrate only justified fixes into the real checkout after reviewing the diff.

## Access-dependent host actions

Complete all independent work first. Then provide the exact candidate identity and
private task parent from the dated record, not placeholders mistaken for a tested pin.

1. Open the prepared target in Cursor editor Agent or Antigravity IDE and start a
   fresh session. Record build, model/effort where exposed, OS, and visible guidance.
2. Select the native skill named in that task's prompt; for baselines verify Remora
   is absent. Paste only that prompt, preserving its authorization boundaries.
3. Retain the response, actual command outcomes, file changes, and discovery state
   in the private result folder. Do not forward prior answers to the next session.
4. Run the prepared comparison and uncovered functional cases, then switch hosts
   on one existing installation with all three families already recorded. Snapshot
   managed/project guidance bytes before and after; switching must not rewrite them.

If no supported automation reaches these exact surfaces, **32 comparison runs remain
across Cursor and Antigravity**, plus uncovered functional/host-switch scenarios.
CLI tests from another surface cannot replace them. Fallback is recorded separately.
Do not bypass permissions or mark unavailable scenarios passed.

Private result form: task ID; date; candidate pin; host/surface/build; model/effort;
OS; skill visible/activated; resources/scoped guidance read; actual commands/results;
changed files; intervention count; rubric judgments with evidence; failures/gaps.
